## 2. 已完成阶段

### 阶段 0：冻结与基线

- 基线提交：`69c979441ebb3ad86b86db26a2c47c83a3a19c70`
- 当前分支：`pr-15-qqmusic`
- 保留现有用户数据、数据库、缓存、登录会话与凭据，未读取或输出任何真实敏感值。
- 未执行合并、推送、标签、Release 或数据库迁移。

### 阶段 1：设置所有权与音源隔离

- 鉴赏家、网易云、Bilibili、QQ 音乐改为各自保存，不再由一个全局保存动作串写多个音源。
- 音源启用状态改为统一快照，并通过变更事件同步给搜索界面。
- 搜索只调用当前明确启用的音源；关闭的音源不显示结果组、不启动后台服务，也不会从搜索页打开设置。
- 网易云首次无配置时默认关闭，必须由用户主动启用。

### 阶段 2：窗口化布局

- 主舞台使用容器可用宽度计算列宽，不再在最小窗口中强行使用宽屏固定列。
- 在 `900px` 进入紧凑双列，在 `1280px` 恢复宽屏比例。
- 补充 `min-width: 0` 与内容层溢出边界，降低标题、歌词和右侧区域互相挤压的风险。

### 阶段 3：QQ 音乐登录与凭据边界

- 提供 QQ 扫码与官方 QQ 音乐窗口内的微信扫码入口。
- 删除通过 `document.title`、本地 TCP beacon 和固定 8KB 缓冲区传递 Cookie 的旧实现。
- WebView2 Cookie 读取、可信域校验、会话验证与保存合并为单个 Rust 命令。
- 二维码引导阶段的 Cookie 只保存在 Rust 内存会话中，不进入 React state。
- 手动导入改为可滚动多行输入；验证失败时不覆盖已有有效凭据，也不自动启用 QQ 音源。

### 阶段 4：网易云服务稳定性

- 前端并发初始化共享同一个 Promise。
- Rust 侧增加异步启动锁，并在获得锁后再次执行健康检查，避免重复启动 Node 子进程。
- 健康检查不再只判断 HTTP 成功，还校验 `/login/status` 是否具有网易云响应结构。
- 应用启动时只初始化已启用音源；服务未知或短暂不可用不会被误报为会话已登出。

### 阶段 5：自动化门禁

- 扩展静态回归检查，覆盖设置串写、关闭音源隔离、旧凭据通道、QQ 二维码边界、网易云单例启动和紧凑窗口布局。
- 新增 Rust 单元测试，验证网易云健康检查只接受正确响应结构。
- 完成 TypeScript、ESLint、Prettier、Vite、Rust fmt、Cargo check、Clippy 和 Cargo test 验证。
